## 现在能做什么

**默认流程已改为本机制品发布（v1.1）**：未提交/未 push 的本机代码 → 本机测试编译打包 → SSH 隧道上传 ZIP → 远端校验并维护切换。不执行 commit/push，远端无需 Git、Go 或仓库凭据；它们只用于保留的可选远端仓库构建。

在网页顶部点击“本机测试并打包”，成功后在对应行点击“上传此包并部署”。本机需 Git 和 Go，`config.json` 的 `local_repo` 指向游戏仓库。构建期间不要编辑源文件；构建前后会比较 Git 跟踪和非忽略的新文件的清单与哈希，变化则不批准此包。忽略文件不在清单内，此检查不是完整文件系统快照。

本机 `local-artifacts/<构建ID>/` 保存 `package.zip`、`result.json`、源码指纹清单及展开包，日志在 `jobs/`。包内 BUILD_INFO 记录 `git_dirty` 和独立的 `local-时间-ID` 版本，HEAD 仅是来源参考，实际发布内容由 ZIP SHA256 标识。构建及上传期间保持本机后台运行，远端确认接收任务后可退出。

新增同事构建电脑还应取得 `local-build.ps1` 和完整 `deploy/` 目录。管理器与 Agent 需同步新版；已有 Agent 时在无活动任务后备份并停止 Agent，更新 EXE、worker.ps1 和 deploy，再启动，保留配置、token、任务、检查点及游戏目录，不重复执行首次安装器。

- 本机浏览器管理，默认 `http://127.0.0.1:18765`。
- SSH 密钥连接远端，管理 API 只监听远端回环 `127.0.0.1:19090`。
- 远端根据已推送的完整 commit SHA，校验允许分支历史、独立检出、测试、编译与生成 ZIP/SHA256。
- 仅构建、构建并部署、启动、维护停服、回滚上一版、恢复中断检查点。
- 真实版本探针、任务历史、日志；网络失败显示未知，不继续显示在线。
- 单任务执行、请求去重、部署前版本比对；切换前保存检查点，失败回滚。
- 远端收到任务后不依赖本机继续在线。Agent 退出时通过 Windows Job Object 终止构建子进程，重启后标记中断；未完成切换要求恢复检查点，不自动重复切服。

**当前是维护发布 v1，尚未实现“等待整局结束”的业务排空。发布、停服、回滚会中断内存对局，必须先安排维护并在界面确认。** 游戏代码、协议、Ruleset 未因本工具而修改。首版不可用于宣称无损升级或无人值守生产发布。

## 一次性安装：本机

双击 `首次接入.cmd`。按提示创建专用 `C:\Users\ZYF\.ssh\zyf_cicd_ed25519`，后台无交互运行需空口令专用密钥（或自行配置解锁后的 SSH agent 并调整连接选项）。不要覆盖现有个人 `id_rsa`。

SSH 首次主机指纹必须已核对并记录；脚本使用 `StrictHostKeyChecking=yes`，不自动信任陌生服务器。之前用户已手动连通该地址；脚本不会复制任何个人私钥到远端。

脚本要求你输入远端 Windows 账户密码一次以安装公钥，密码不写入文件、不发到聊天。若远端管理员账号受 UAC 筛选，安装公钥可能需要在远端管理员终端手工完成；不要关闭 UAC 或全局放宽 sshd 策略。

Windows 默认管理员账号的公钥通常位于 `C:\ProgramData\ssh\administrators_authorized_keys`；普通账号位于用户 `.ssh\authorized_keys`。按远端 `sshd_config` 的实际 Match 规则确认。脚本保留已有公钥条目。

本次实际接入遇到远程公钥写入“拒绝访问”：本机专用密钥已生成，SSH 已确认提交该公钥但服务器未接受。无需重新生成密钥；已提供 `remote-authorize-key.ps1`，其中只有本次生成的公钥。将其复制到远端，在远端管理员 PowerShell 执行即可安装到 Windows 默认管理员公钥文件；原文件先备份。不需要关闭 UAC、放开空密码或修改全局 SSH 鉴权策略。如果重新生成了本机密钥，需同步更新该脚本中的公钥。

## 可选：远端仓库构建并发布

1. 在游戏仓库明确提交范围并 push。本工具不会执行 commit 或 push。
2. 后台“读取本机 HEAD”填写完整 SHA；存在未提交改动时会提示，这些改动不会出现在远端版本里。
3. 先“仅构建与测试”。远端只允许配置的 `斗蛐蛐` 分支历史上的提交，不接受任意仓库 URL、脚本或命令。
4. 确认客户端已经支持该提交的协议、表现与 Ruleset。客户端影响单和固定任务通知仍由游戏仓库流程负责；管理器只要求人工确认，不自动推断兼容性。
5. 安排维护、勾选影响确认，执行“构建并部署”。旧服在拉代码、测试、编译阶段继续运行。
6. 成功后同时查看“当前运行版本”和任务日志。只看到 ZIP 或“构建成功”不代表已切服。

同一任务只执行一次。提交响应丢失时使用“查询 / 重试上次提交”；不要重复点击发布创建多个任务。历史任务和日志保存在远端 `jobs/`。

## 失败、中断与维护

- 拉取/测试/构建失败：旧服不切换，查看任务日志。
- 停止后切换或启动失败：尝试恢复旧版本，发布任务仍标失败，日志显示恢复结果。
- 恢复失败/机器重启：检查点保留，后续操作被阻止；先使用“恢复中断检查点”。不要手工删除 checkpoint 绕过恢复。
- 切换时暂设游戏服务为手动启动，避免断电重启后直接启动未验收的版本；完成验收后恢复自动启动。
- Agent 正在执行任务时拒绝普通 Stop 请求；系统关机仍会中断，恢复依赖检查点。暂不提供强制取消按钮。
- 构建限制 Go 并行度并设置 45 分钟任务上限，但同机测试/编译仍可能影响在线延迟。
- 首版保留构建目录、制品与日志供排错，不自动清理。定期检查磁盘；清理前先确认没有活动任务，保留当前、上一版本和检查点引用制品。
- 数据库迁移没有自动编排能力；只部署无数据库结构迁移的可信版本。

## 权限边界与现阶段限制

这是单管理员、可信私有代码的临时部署工具。首版构建与部署由同一个服务账户执行；该账户可控制游戏服务，因此仓库测试/脚本也拥有这个账户的权限。尚未实现独立低权限构建沙箱，不接收外部 PR 或不可信分支。正式生产前应拆分构建身份、增加发布审批/签名、客户端兼容性机器校验、日志保留和业务排空。

使用现成 Windows Service、OpenSSH、Git 和 Go，不需要购买云效 CI/CD；设备、电力、网络及现有代码托管额度仍由用户提供。

## 2026-09-21：配置权威源改为部署包（网页配置面板只读）

> 历史记录，以下“包覆盖 shared”不再是当前操作规则。普通部署保留已有 shared 配置；Redis 玩法/经济与 host 会话策略分别通过上述入口管理，不通过重新打包覆盖现场数值。

之前“配置留在服务器、发布只读校验”的策略有一个直接后果：**配置结构一变，管理工具就必须改**——文件名、字段列表、校验流程都写在工具里（`native_config.go` 的文件名常量、`ui.html` 的下拉框、校验时写死的三份文件）。

现在改为**部署包是玩法/经济配置的唯一权威源**，工具对 schema 完全无知：

- 包根目录带齐 `host.json`/`gameplay.lua`/`economy.lua` 时，部署**整文件替换**现场 `shared/` 下的同名文件；结构增删改字段不需要动本工具，只要在游戏仓库改并重新发布。
- 三份文件只出现一两份 = 构建缺陷，在停服前拒绝部署。三份都没有的旧包仍走一次性的 `shared/server.json` 迁移，迁移后进入包覆盖模式。
- `shared/native-data`（玩家数据/WAL）与 `shared/.env`（机器选择器）由服务器持有，任何情况下不被包覆盖。
- 部署前用包内 `current/server.exe -preflight` 预检包内配置：**校验不通过就不切服**。
- `shared/RULES.md` 由部署程序生成并说明以上规则；`.env` 增加 `CONFIG_POLICY=release_owned`。
- 网页“远端玩法配置”“新版服务器配置”改为**只读诊断**：GET 返回现场文件与哈希，任何 POST 一律拒绝，既不写文件也不启动校验子进程。改配置走“在游戏仓库修改 → 打包 → 维护部署”。

回滚语义要记住：代码回滚不回滚配置，`shared/` 中的三份文件始终来自最近一次部署的包；旧版本程序可能不接受新结构，此时恢复会失败并保留检查点，应发布前向兼容的包，不要手工改配置绕过。此前“用前向兼容的包，不要用旧 DLL 对当前 WAL 回滚”的限制不变。

这是上 Redis 之前的前置形态：配置由“发布产物的一部分”变成“运行时状态”。上 Redis 时包内配置退化为种子，另需先定回滚一致性（key 带版本或发布快照）与降级策略（拒启或用本地快照兜底）。

验证：Go 测试与 vet 通过（只读面板的 GET/POST、缺失文件、revision 变化、拒绝写入后文件与备份不变）；隔离 Worker 演练 8 个场景通过（包内配置整体替换、现场手工值被覆盖、缺份拒绝部署、旧包迁移、native-data 与 .env 未动、预检失败保持停服、不确定启动保留 WAL 并前向恢复）。
